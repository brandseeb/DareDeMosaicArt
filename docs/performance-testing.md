# 実機パフォーマンス計測手順

このアプリの DEBUG ビルドには、重い処理を Instruments と Xcode コンソールで確認できる計測点が入っています。配布用の Release ビルドでは計測処理は実行されません。

## 計測する操作

1. Xcode の `Product > Profile` から実機で起動する。
2. Instruments の `Points of Interest`、`Time Profiler`、`Core Animation`、`Allocations` を使用する。
3. コンソールでは `[PERF]` で絞り込む。
4. 各条件をアプリのコールド起動後と、同じ作品を2回目に開いた状態の両方で測る。

| 計測名 | 対象 |
| --- | --- |
| `project.hydration` | 作品を開いた際のタイル画像復元 |
| `mosaic.preview.render` | 数千タイルから表示用の結合画像を生成 |
| `photos.cache.load` | 解析済み写真インデックスの読込 |
| `photos.library.scan` | 写真ライブラリの差分照合・解析 |
| `candidates.index.build` | 類似写真検索インデックス構築 |
| `candidates.search` | 選択ピースの類似写真検索 |
| `mosaic.initial.matching` | 新規作品の初期写真割り当て |
| `timelapse.export` | 10秒タイムラプスの生成 |

## テストマトリクス

- グリッド: 10×10、20×20、40×40、60×60
- 写真ライブラリ: 約1,000枚、5,000枚、10,000枚
- 操作: 作品を開く／閉じて再度開く、ズーム、スクロール、ピース選択、候補の初回表示、新規作成、完成画像表示、タイムラプス生成

## 判定の目安

- ズーム・スクロール中の長い Main Thread 停止がないこと。
- 画面操作中のフレームレートが基本60fpsを維持すること（ProMotion端末では最大120fps）。
- キャッシュ済み候補はタップ後おおむね300ms以内に先行表示されること。
- 100msを超える処理はメインスレッドから外れていること。
- 同じ作品の2回目表示が初回より遅くならず、メモリが操作ごとに増え続けないこと。

数値が基準を超えた場合は、同じ時間帯の Time Profiler のスタックを確認し、該当する計測名単位で改善します。
